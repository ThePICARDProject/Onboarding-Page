A focused step toward Devine’s research vision

This semester’s direction

The goal is to turn PICARD2’s technical foundation into a focused, complete scientific experiment loop. The semester-end state supports reliable execution of one representative algorithm, understandable results, and study of how parameter choices change those results.

Semester destinationOne thesis-relevant algorithm and representative dataset can be configured with typed values, executed through PICARD2’s real Spark path, observed from submission through completion, and evaluated either as one experiment or as a structured parameter sweep.

Three required outcomes

01

Reliable experiment

A documented algorithm and data contract runs repeatedly through the queue and Spark. Validation, lifecycle, reruns, and failures behave predictably, and automated evidence proves the path.

02

Understandable result

The portal shows what ran, the resolved configuration, execution status and timing, readable logs and errors, a scientific metric or summary, and the resulting artifact.

03

Parameter sweep

A researcher defines a bounded grid of values, previews the trials, submits once, follows progress, preserves partial results, and compares completed trials by meaningful metrics.

The product experience at semester end

Select algorithm + data→Configure fixed values or ranges→Review experiment→Run on Spark→Monitor→Interpret + compare

For one experiment

The researcher chooses a dataset, completes a parameter form generated from the algorithm contract, reviews the resolved setup, submits, monitors the run, and receives an interpretable result.

For a parameter study

The same configuration can assign finite ranges or value lists to selected parameters. PICARD previews the Cartesian combinations and treats each as an ordinary, reproducible trial.

For later review

Experiments and sweeps remain discoverable with their configuration, lifecycle, scientific metrics, logs, errors, and artifacts. Completed trials can be compared without reconstructing them manually.

Near-term progression

1 · Establish the representative research contract

A thesis-relevant algorithm and representative dataset establish the first complete PICARD2 path, including inputs, typed parameters, expected outputs, scientific metrics, and the target environment.

Milestone: one concrete, versioned example defines a valid experiment and result.

2 · Repair and prove the single experiment

Make startup reproducible and repair routing, invocation, parameter forwarding, storage, lifecycle, logging, error handling, and rerun behavior on that path.

Milestone: the representative experiment succeeds or fails predictably from a clean environment.

3 · Present scientific results

Persist the resolved configuration and result schema, then make metrics, summary, timing, logs, errors, and artifacts understandable in the portal.

Milestone: a researcher can interpret the experiment without direct database, worker, or filesystem access.

4 · Implement and harden parameter sweeps

Add typed ranges, exact trial preview, atomic batch creation, capacity-aware scheduling, aggregate progress, failure isolation, stop behavior, and comparison of completed trials.

Milestone: the full study can be configured, run, revisited, and interpreted through PICARD2 with automated end-to-end evidence.

Part of the longer vision

  • Online learning and streaming data

This boundary keeps the semester achievable. Every delivered capability contributes to the longer research trajectory.

After the first experiment loop

Once one scientific experiment loop is dependable, the project can add more research capability through a shared product structure. New algorithms can publish the same kinds of parameter and result contracts; new pipeline stages can compose around the same execution records; and new interfaces can compare experiments using durable scientific evidence.

One proven experiment contract→More research algorithms→Complete workflow→New domains→Streaming research
