Presentation Layer

The React + Vite single-page application that users interact with. It owns rendering, routing, client-side validation, and the authentication/workspace state — but no business logic and no persistence.

New generation

This page describes the new-gen frontend in picard_new_generation/PICARD2/frontend. It is a hand-built LCARS-themed SPA — not the old MUI/Axios/Google-OAuth frontend. There is no Tailwind/MUI, no Axios, and no WebSocket; data flows over plain fetch with session cookies, and live output is polled.

Provider composition

The app is wrapped in nested context providers in main.jsx. Anything inside can read theme, sound, auth, or workspace state without prop-drilling.

Authentication flow

Auth is GitHub OAuth, mediated by the Django backend. The frontend never talks to GitHub directly, and there is no token in localStorage — the session lives in a cookie.

  1. Sign in. The user clicks GitHub sign-in; AuthProvider.login() sends them to the backend's GitHub OAuth start endpoint.
  2. OAuth round-trip. GitHub authorizes and redirects back to the backend, which creates/looks up the Django user and establishes a session.
  3. Session cookie. Subsequent API calls include the session cookie (credentials: 'include'); AuthProvider reflects the authenticated user.
  4. Logout. AuthProvider.logout() clears the backend session and resets local state.

Experiment workflow (user perspective)

  1. Submit page. Upload a dataset (CSV) and an algorithm (Python/JAR). Optionally declare typed algorithm parameters (name, type, default, driver index) with the add/remove row builder.
  2. Create experiment. Pick a script + dataset, optional args, and optionally open Advanced Settings to set cluster resources (executors/nodes, cores, driver/executor memory). Creates a Pending experiment.
  3. Runs console. Queue/Run the experiment. The page polls the detail endpoint and renders live output and the status badge. A Cancel Run button appears while it's active.
  4. Results. When a result exists: download it, or use the Data Visualization panel to plot two result columns (line/bar/scatter).
  5. Aggregate. Tick multiple experiments in the list and Download Selected to get a zip of their results.

Theming

Two themes ship together. LCARS (Star Trek-inspired, dark, dense) is the default. WVU Light is an opt-in alternative for readability — white background, WVU blue (#002855) headers, WVU gold (#EAAA00) accents. The toggle lives in the LCARS sidebar; the choice persists across sessions via localStorage. The light theme is pure CSS scoped under body.light-theme, so it never alters the LCARS default.

Talking to the API

All network access is funneled through WorkspaceProvider, which calls apiRequest() from lib/api.js. The endpoints it uses map directly to the application layer routes — e.g. POST /experiments/create/, POST /experiments/{id}/run/, POST /experiments/{id}/cancel/, GET /experiments/{id}/visualization/, and POST /experiments/aggregate/.
