PICARD is migrating.

PICARD2 replaces the legacy stack with React, Django, Celery, Redis, MySQL, and a standalone Spark cluster. It is the codebase the incoming implementation team should develop—but its central experiment path still needs repair and several required PICARD1 concepts have not yet been reimplemented.

Understand PICARD2 → See the implementation plan
Team directive Stabilize and complete the selected migration before implementing hyperparameter sweeps. PICARD1 is evidence of prior behavior, not a specification to copy blindly.

The situation in one minute

What is new

A cleaner Django/DRF API, React 19 frontend, GitHub organization login, UUID-owned public/private assets, Celery/Redis queueing, and Spark standalone execution.

What works on paper

Authentication, CSV and Python/JAR asset management, experiment records, asynchronous queueing, status polling, and a containerized local topology are present in the code.

What is broken

UUID routes, argument forwarding, JAR command ordering, log serialization, result naming/storage, rerun cleanup, and parts of validation prevent calling the single-run path reliable.

What is missing

Structured parameters and results, run names and lifecycle detail, cancellation, robust tests, and product decisions on large uploads, aggregation, export, and visualization.

Current State of PICARD: status and plan

This high-level brief explains why the team is prioritizing completion of the PICARD2 migration before implementing parameter sweeps. It summarizes the system's current gaps, the phased plan for reaching a stable and testable foundation, the intended end state, and the context being handed to incoming design and implementation teams.

Order of work

Align retained scope→Make startup reproducible→Repair one complete run→Restore sweep-ready domain model→Complete selected parity→Build sweeps

The immediate success target is an authenticated user who can manage supported assets, configure a structured experiment, run it reliably on Spark, observe and cancel it, inspect/download results, and recover sensibly from failures.
