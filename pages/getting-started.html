The conceptual shape of PICARD

The research experiment model

PICARD is organized around reproducible research experiments rather than infrastructure commands. Algorithms and datasets provide the inputs; configuration defines the trial; distributed execution performs the work; and results preserve the evidence.

Research question→Algorithm + dataset→Resolved configuration→Distributed run→Scientific result→Next question

People around a PICARD experiment

Researcher

A student, faculty member, or collaborator who brings the scientific question, chooses the experimental inputs, interprets results, and decides what to investigate next.

Algorithm author

A researcher or developer who prepares a distributed algorithm and describes its compatible inputs, typed parameters, execution entry point, outputs, and metrics.

Platform operator

A maintainer who keeps shared computing resources available, protects capacity, and investigates infrastructure or execution failures.

One person may occupy several roles. The roles describe responsibilities around an experiment rather than separate account types in the current implementation.

Core concepts

ConceptMeaning in PICARD
AlgorithmA versioned research method with a documented input contract, ordered typed parameters, an execution entry point, and a result contract.
DatasetA versioned research input with identity and enough metadata to establish compatibility and reproduce an experiment.
ExperimentOne immutable, resolved combination of algorithm, dataset, parameter values, and relevant execution context.
ParameterA named, typed, constrained algorithm setting. It has one resolved value in an experiment and may contribute multiple values to a sweep.
SweepA parameter study containing a finite set of related experiment trials generated from one search-space definition.
TrialAn ordinary experiment belonging to a sweep, with one fully resolved parameter combination and its own lifecycle and result.
ResultThe evidence produced by a run: scientific metrics and summary, execution measurements, provenance, diagnostics, and artifacts.

One experiment

A single experiment follows one continuous lifecycle:

  1. An algorithm and compatible dataset establish the experiment’s inputs.
  2. The algorithm contract supplies typed parameters, defaults, constraints, and explanatory metadata.
  3. Resolved parameter values and input identities form an immutable experiment configuration.
  4. PICARD persists and queues the experiment before Spark execution begins.
  5. Status, timing, logs, and errors accumulate while the experiment runs.
  6. Successful execution produces scientific metrics, a summary, and one or more result artifacts.
  7. The complete record remains available for interpretation, comparison, and reproduction.

A parameter study

A sweep extends the single-experiment model. Selected parameters contain finite ranges or value lists while the remaining parameters stay fixed. PICARD expands the Cartesian combinations into ordinary child experiments.

Define search space→Count combinations→Create trials→Run within capacity→Aggregate progress→Compare results

Bounded definition

The search space is finite and validated, with an exact trial count and a configured safety limit.

Atomic record

The sweep definition and child configurations exist before execution starts, independent of an open browser session.

Ordinary trials

Every child uses the same experiment lifecycle, result contract, authorization, and execution path as a standalone run.

Collective outcome

Aggregate progress, partial failure, preserved completed work, and metric comparison describe the study as a whole.

Result layerContentsPurpose
Scientific outcomePrimary objective, class-aware metrics, summary values, and domain-specific interpretation data.Answers what the experiment learned or produced.
Execution evidenceFinal state, timestamps, duration, and relevant performance measurements.Shows whether the method ran successfully and efficiently.

ArtifactsGenerated files, models, predictions, tables, or other algorithm-defined outputs.Preserves the detailed evidence for later analysis.

Open product boundaries

The near-term direction defines a complete experiment loop while leaving several details dependent on the representative research workload:

  • The first thesis-relevant algorithm and representative dataset.
  • The exact parameter types, units, constraints, and supported range forms.
  • The scientific summary, metrics, artifacts, and comparison semantics for that algorithm.
  • The safe sweep size, execution capacity, and meaningful forms of progress.
  • The behavior of already-running work when a sweep stops.
  • The first deployment environment, access model, and expected interruption behavior.

These boundaries can evolve without changing PICARD’s core identity: a reproducible distributed experimentation platform for continued research.
