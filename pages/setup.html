Setup

How to go from a fresh clone to a running PICARD new-generation stack (Django + React + Celery + Spark) via Docker Compose.

New generation

These instructions target picard_new_generation. They replace the old 481-FrontEnd + dotnet run flow. The whole stack now comes up with one docker compose up.

Prerequisites

  • Docker and Docker Compose (the supported way to run everything together)
  • Membership in the ThePICARDProject GitHub org
  • A GitHub OAuth app (for login — see below)
  • Optional, for local dev without Docker: Python 3.11+, Node/npm, a MySQL instance, and Redis

Clone the repo

git clone git@github.com:ThePICARDProject/picard_new_generation.git
cd picard_new_generation/PICARD2

The Compose file lives at PICARD2/docker-compose.yml.

Environment file

The backend and database read configuration from backend/.env. Copy the template and fill it in: 

cp backend/.env.example backend/.env
VariablePurpose
DJANGO_SECRET_KEYDjango secret — set a real value
DEBUGTrue for local dev
ALLOWED_HOSTSComma-separated hosts (default covers localhost)
DB_NAME / DB_USER / DB_PASSWORDMySQL credentials (DB_HOST=db in Compose)
MYSQL_DATABASE / MYSQL_ROOT_PASSWORDUsed by the db container
FRONTEND_LOCAL_URLDefault http://localhost:3000 (CORS/CSRF origin)
GITHUB_OAUTH_LOCAL_CLIENT_ID / _SECRETFrom your GitHub OAuth app
Don't commit secrets

backend/.env holds real credentials — it is gitignored, keep it that way. Only .env.example (placeholders) belongs in version control.

GitHub OAuth app

Login uses GitHub OAuth. Create an OAuth app under your account (or the org) at Settings → Developer settings → OAuth Apps:

  • Homepage URL: http://localhost:3000
  • Authorization callback URL: the backend's GitHub callback (served from the Django authentication app)

Put the resulting client id/secret into GITHUB_OAUTH_LOCAL_CLIENT_ID and GITHUB_OAUTH_LOCAL_CLIENT_SECRET in backend/.env. The requested scope is read:user user:email read:org.

Run with Docker Compose

cd PICARD2
docker compose up --build

This brings up every service. On start, the backend container runs python manage.py migrate automatically, then the dev server. The services are:

  • db (MySQL), redis (Celery broker)
  • backend (Django API), celery_worker (runs experiments)
  • frontend (React via nginx)
  • spark-master + spark-worker (the Spark cluster)

To stop: docker compose down (add -v to also drop the MySQL volume).

Ports

ServiceHost portWhat it is
frontend3000The app — start here
backend5000Django REST API
db (MySQL)3307 (MYSQL_PORT)Database

spark-worker UI8081Spark worker web UI

Open http://localhost:3000 and sign in with GitHub.

Local dev without Docker (optional)

If you want to iterate on one piece without the full stack:

Backend

cd backend
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
# point DB_HOST at a reachable MySQL, then:
python manage.py migrate
python manage.py runserver

You'll also need Redis and a Celery worker for experiment execution:

celery -A backend_config worker --loglevel=info --concurrency=1

Frontend

cd frontend
npm install
npm run dev      # Vite dev server
npm run build    # production build

Set VITE_API_BASE_URL so the SPA can reach the API.

SSH gateway access (deployed environment)

To reach PICARD hardware behind the WVU network you still go through the SSH gateway. (This part is unchanged from the old gen.)

  1. Request gateway access. Submit the WVU service desk form; use 157.182.194.132 as the destination IP.
  2. Verify gateway access. 
    ssh <your-username>@ssh.wvu.edu
  3. Hop to the PICARD server (account created by a team member): 
    ssh <your-username>@picard.csee.wvu.edu

A convenience ~/.ssh/config with a ProxyJump through the gateway still works — just forward whatever port the deployed service is on (the new gen frontend is 3000, the API 5000).
