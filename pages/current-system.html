PICARD2 · active codebase

Current system

PICARD2 is a rewrite, not a framework-for-framework port. It has better service boundaries and useful new behavior, but static presence does not prove an end-to-end workflow.

React 19 SPA→ session + CSRF →Django / DRF→MySQL + media
Django / DRF→Redis→Celery worker (concurrency 1)→ spark-submit →Spark master→Spark worker

The local topology is defined in PICARD2/docker-compose.yml. Uploaded files live in Django media storage; Spark inputs and outputs also cross shared Docker volumes.

Intended user flows

Authentication

GitHub OAuth, organization gate, cookie-backed Django session, and CSRF token. Password endpoints exist but are not exposed in the current UI.

Asset management

Upload, list, share privately/publicly, and delete CSV datasets and Python/JAR scripts through the workspace provider.

Experiment execution

Create a pending experiment, queue it through Celery, invoke spark-submit, and poll summaries every 12 seconds.

Results

The application should write to a supplied result path and Celery should import the artifact. The current contracts disagree, so this is not coherent yet.

Confirmed high-priority defects

  1. UUID primary keys are routed through integer URL converters.
  2. The worker and API use incompatible result filenames and locations.
  3. Experiment detail returns a file field instead of reading log text.
  4. Stored experiment arguments are never passed to spark-submit.
  5. JAR --class options are placed after the application resource.
  6. Result ownership is split across Django storage and a shared Spark volume.
  7. Rerun cleanup and referenced-asset deletion semantics are unsafe or ambiguous.
  8. Important upload checks exist only in the browser.
  9. The Python/JAR invocation and output contract is undocumented.

What has been validated

Static assessment, not a runtime certificationPython source compilation passed on 2026-07-16. The frontend build could not start because dependencies were not installed. The full Docker stack, authentication flow, and Spark experiment path have not yet been proven from a clean environment.
